Docker Quick Start

CapScope works on any Docker host. One container, one volume, one password.

What every platform needs

Set AUTH_PASS (a long random password). Without it the server refuses to start. Persist /data on a volume — the SQLite database lives there. Give CapScope Docker API access via /var/run/docker.sock or a read-only socket proxy. Run exactly one replica.

Before you start

Generate a password first (used everywhere below):

openssl rand -base64 24

Option A: docker run

docker run -d --name capscope \
  -p 8080:8080 \
  -e AUTH_USER=admin \
  -e AUTH_PASS='a long random password' \
  -v capscope-data:/data \
  -v /var/run/docker.sock:/var/run/docker.sock \
  --restart unless-stopped \
  ghcr.io/hacrex/capscope:latest

Open http://<host>:8080 and log in.

Option B: Docker Compose

services:
  capscope:
    image: ghcr.io/hacrex/capscope:latest
    ports:
      - "8080:8080"
    environment:
      AUTH_USER: admin
      AUTH_PASS: change-me        # change this before exposing the port
      MAX_DB_MB: 2048
      EXCLUDE: "^captain-"
    volumes:
      - capscope-data:/data
      - /var/run/docker.sock:/var/run/docker.sock
    restart: unless-stopped

volumes:
  capscope-data:
cd deploy
docker compose up -d --build
# then open http://:8080

AUTH_PASS defaults to change-me in the compose file — change it before exposing the port.

Verify it works

  1. curl http://<host>:8080/healthz → ok (no auth required).
  2. Log in with Basic auth; the sidebar lists containers within ~10s of first deploy.
  3. Open a container → Live tail streams (SSE).
  4. Crash a throwaway container → Crashes tab shows a snapshot.

Safer: socket proxy

Mounting docker.sock is root equivalent on the host. To limit what CapScope can do, run a read-only socket proxy:

  socket-proxy:
    image: tecnativa/docker-socket-proxy
    environment:
      CONTAINERS: 1
      EVENTS: 1
      PING: 1
      POST: 0
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro

Then remove CapScope's socket mount and set DOCKER_HOST=tcp://socket-proxy:2375 on the CapScope service.

Environment variables

VariableDefaultMeaning
AUTH_USER / AUTH_PASSadmin / noneBasic auth. Server refuses to start without AUTH_PASS
ALLOW_NO_AUTHfalseSet true to run without auth (local testing only)
LOG_RETENTION7dDelete logs older than this (d, h, m)
METRICS_RETENTION7dSame for CPU/memory samples
MAX_DB_MB1024Hard cap on database size; oldest data dropped first
STATS_INTERVAL10sMetric sample interval per container
EXCLUDEnoneRegex to exclude containers (noisy ones like ^captain-)
SNAPSHOT_KINDScrash,oomWhich stops create crash snapshots

Full list in the README configuration table.

Troubleshooting

SymptomLikely cause / fix
Container exits instantly with "AUTH_PASS …"Password not set — set it in the environment
Sidebar emptySocket not mounted / wrong path / EXCLUDE too greedy
Live tail stallsReverse proxy buffering SSE — honor X-Accel-Buffering: no or disable buffering on /api/logs/stream
Data gone after redeploy/data not on a persistent volume
Corrupt DB / locked errorsMore than one replica running against the same volume — scale to 1
Not supported:

Kubernetes (CapScope talks to the Docker Engine API, not the kubelet). Run CapScope as a Docker container on a Docker node instead.
