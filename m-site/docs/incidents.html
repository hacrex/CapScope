Incident management

Turn alert firings into operational workflow. Incidents are tracked with open / acknowledge / resolved states, linked to the alerts and crash snapshots that triggered them — a single view for on-call.

Incident lifecycle

StateMeaning
openThe incident is active and being worked on
ackSomeone has acknowledged ownership of the incident
resolvedThe incident is resolved; ended_at is set

Incident fields

FieldMeaning
titleHuman-readable incident title
severitycritical, warning or info
stateopen, ack or resolved
started_atWhen the incident first fired (unix ms)
ended_atWhen the incident was resolved (unix ms; 0 if still open)
related_alert_idsJSON array of alert firings associated with this incident
appApplication the incident is scoped to
host_idHost the incident occurred on (multi-node setups)

API

GET /api/incidents List incidents, filterable by ?state= and ?app=
GET /api/incidents/{id} Get a single incident with full details
POST /api/incidents/{id}/state Change state — body: {"state": "open|ack|resolved"} (admin only)

Incident management is admin-only for writes; viewers can read incidents for their assigned applications.

In the UI

The Incidents tab shows a table of all incidents with severity badges and state chips. Filter by state (open / ack / resolved) or search by app or title. Click an incident to open its detail view where you can transition its state.

Auto-creation: incidents are created automatically from alert rule firings and auto-resolved when the rule stops firing — no manual setup required for common cases.
