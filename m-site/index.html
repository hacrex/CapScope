Self-hosted container observability

Persistent logs and crash snapshots for Docker containers.

CapScope runs alongside your containers, stores logs and CPU/memory samples in SQLite, and keeps a crash snapshot every time a container exits non-zero or is OOM killed. When a container is redeployed and disappears, its history stays searchable.

Quick start Documentation

The problem

When a Docker container is replaced on redeploy, its stdout, stderr, and stats are gone. Live-only viewers like Dozzle show the present, but can't answer "what happened before it died?"

Lost on redeploy: Logs, memory trends, exit codes, and crash context disappear with the container.
Heavy stack: Prometheus + Grafana + Loki is overkill for a single server or homelab.

CapScope

⬤
Persistent history. Logs and metrics stored in SQLite with retention policies.
⬤
Crash snapshots. Auto-captured on OOM or non-zero exit with exit code, memory trend, and last log lines.
⬤
One binary. Single container, single volume, no external database.

Features

Everything you need to debug container failures.

Persistent logs

Logs stored in SQLite with full-text search. Search history long after a redeploy removes the container.

Crash snapshots

Auto-saved on OOM or non-zero exit with exit code, memory trend, last lines, and a rule-based summary.

Metrics history

CPU and memory samples persisted per app or replica, from 15 minutes to 7 days.

Restart-loop detection

Flags containers dying in a loop so you know when an app is crash-looping.

Access-log dashboard

GoAccess-style panels from your reverse proxy: status codes, top paths, client IPs, CSV export.

Deploy markers

Correlate crashes and metric spikes with the release that preceded them.

Docker

Quick start

docker run -d --name capscope \
  -p 8080:8080 \
  -e AUTH_USER=admin \
  -e AUTH_PASS='change-me' \
  -v capscope-data:/data \
  -v /var/run/docker.sock:/var/run/docker.sock \
  --restart unless-stopped \
  ghcr.io/hacrex/capscope:latest

Open http://localhost:8080 and log in. AUTH_PASS is required — the server refuses to start without it.
